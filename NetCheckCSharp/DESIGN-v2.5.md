# NetCheck v2.5 / v2.6 调整方案：常用 / 高级分组 + 高级组升级扩充 + 补 IPv6

> 状态：**P0 已落地并验证**（分组 + 高级组默认收起）；P1（路径分析）、P2（IPv6）待做。
> 已按反馈确定：分组措辞「**常用 / 高级**」、IPv6 卡片位置（索引 2）、
> 「高级」组由 2 项**升级扩充为 4 项**、连接诊断默认目标用 `@egress`。
> 第九节已无待确认项 —— 全部决定就绪，按 P0 → P1 → P2 推进。

---

## 一、要解决的问题

v2.4 之后界面有 8 张卡片，全部平铺、全部默认展开。实际用起来有四个问题：

1. **卡片性质混杂**。前六项是「常用」（点一下就有结论，日常体检），后两项是「高级」（已知有问题才用，属于排查）。
   混在一起会稀释常用检测的核心价值 —— 用户点开工具看到 8 张卡片，不知道哪个该点。
2. **MTU 探测占了不成比例的版面**。它 99% 的情况下只产出一行「1500，正常」，
   却和「连通性」「DNS」这种信息量大的卡片平级。
3. **整个工具是 IPv4 单眼视角**。IPv6 在国内移动网络已基本普及，
   「有 IPv6 地址但上游不通」「双栈反而变慢」是当前很常见的故障，而现在完全看不到。
4. **「高级」组里装的是「常用检测的加长版」，不是真的高级能力**。
   路径只探一次、端口只回答通不通、缺 inbound 视角、DNS 看不到现代特性。
   分组把这两项挪出默认视野只是解决了「不打扰」，**没有解决「它们本身太浅」**。

---

## 二、目标与非目标

**目标**

- 默认界面一眼能分清「该点哪个」
- 排查能力一个都不砍，只是不占默认视野
- 补上 IPv6 这个维度缺口
- **把「高级」组做成真的高级** —— 每一项都能回答「问题出在哪个环节」，
  而不是只给一个「通 / 不通」

**非目标（明确不做）**

- 不重排常用组已有卡片的顺序
- 不改成标签页 / 抽屉 —— v2.3 刚从标签页改成卡片流，回退没有收益
- 不加新的全局按钮
- **不为凑数而扩充**（详见第十节）

## 四、逐项改动

### 4.1 分组标题（新增 UI 元素）

一行小字 + 右侧计数，插在卡片流里：

```
── 常用 ─────────────────────────────────
── 高级 ────────────── 4 项 · 点击展开 ───
```

- 样式：13px、`MutedBrush`、左侧无缩进、上下留白 6px，**不套卡片外壳**（它只是个分隔标签，套了就和卡片混淆）
- 整行可点击 = 批量收起 / 展开该组内所有卡片
- 右侧计数显示「N 项」；组收起时追加「点击展开」

**关键约束：分组标题不引入第二套折叠机制。**
它点击后调用的就是现有的 `SetAllCollapsed` 的按组版本 —— 逐张调 `SetCollapsed`。
折叠状态仍然按**卡片键**存进 `CollapsedCards`，不新增字段。
否则「组收起」和「卡片收起」两套状态会互相打架。

### 4.2 「路径」合并并升级为「路径分析」

**改法**：`trace` 与 `mtu` 两个任务合并成一个 `path`，一次跑完：

1. TTL 递增做逐跳追踪，拿到跳表
2. 到达目标后，在**最后一跳**上做 DF 二分查找测路径 MTU

**为什么合并**：

- 两者用的是同一套 ICMP 机制，分开跑等于把同样的包发两遍
- 分开时 MTU 单独占一张卡片，而它的输出通常只有一行
- 合起来后「这一跳慢」和「这一跳 MTU 小」能放在同一个上下文里看 —— 很多 MTU 问题就出在某条隧道上，
  合并后才能对上号

**升级点：每跳探测 3 次，产出丢包率**

现在 `Traceroute.TraceAsync` 每跳只发一个包，把「这一跳偶发丢包」和「这一跳稳定」混为一谈 ——
而路由问题**往往表现为间歇性丢包，而不是持续高延迟**。单次探测看不见它。

改法：每跳发 3 个包，产出

| 字段 | 含义 |
|---|---|
| `MinMs` / `AvgMs` | 该跳的往返延迟（多次取最小 / 平均，最小值的抗噪性更好） |
| `LossPercent` | 该跳的丢包率（3 次里丢了几次） |
| `Responded` | 是否有过响应；全程无响应显示 `*`，**不叫「失败」** |

**`*` 和「失败」必须区分开**：中间路由器不回 ICMP 是**正常现象**（很多骨干设备限速或屏蔽 ICMP），
现在把它显示为「超时 / 失败」会误导用户以为链路断了。真实断链的判据是
**连续多跳无响应且目标不可达**，不是单跳无响应。

**新增结论**

- **第一处丢包跳**：从哪一跳开始出现丢包 —— 这是定位「哪家运营商的问题」的关键
- **延迟突增跳**：相邻跳延迟差 > 50ms 时标注出来，通常意味着跨网 / 跨境出口
- 路径 MTU 分档沿用 `Thresholds.Mtu`

**兼容**：`--check trace` 和 `--check mtu` 保留为别名（都展开成 `path`），
否则已发出去的脚本会失效。

**卡片变化**：标题栏从两个按钮变成一个按钮。

### 4.3 新增「IPv6」卡片（位置：紧跟「本机网络配置」）

**放在「本机网络配置」之后、「连通性」之前，插到索引 2。**

理由：

1. **数据源是同一个。** IPv6 地址本来就来自 `NetworkInterface.GetAllNetworkInterfaces()` 的
   `UnicastAddresses` —— 和「本机网络配置」读的是同一个 API 的同一个集合，
   只是现在只取了 `InterNetwork` 那一半。两张卡片天然是「我的地址栈长什么样」的上下半场。
2. **它是本机信息，不是网络性能。** 排在「连通性」「DNS」这些**测网络**的卡片前面，
   阅读顺序才对：先知道「我有什么地址」，再问「这些地址通不通、快不快」。
3. **失败时不会白跑。** 没有全局 IPv6 地址时，后面的出口查询和可达性探测直接跳过，
   卡片瞬间给出「未启用 IPv6」—— 放在「连通性」旁边的话，用户会期待它有延迟数字。

```
本机网络配置   ← 网卡 / IPv4 / 网关 / DNS / 代理
IPv6          ← IPv6 地址 / 出口 / 可达性   ← 新增，插在这里
连通性        ← 延迟 / 带宽
DNS
NAT 类型
```

**检测内容**

| 项 | 方法 | 说明 |
|---|---|---|
| 全局 IPv6 地址 | `NetworkInterface` 的 `UnicastAddresses` 里筛 `InterNetworkV6`，排除 LinkLocal / 回环 / 临时地址 | 纯本地，瞬时 |
| IPv6 出口 IP | `HttpClient` 强制走 IPv6 查一次公网 IP | 用 `SocketsHttpHandler.ConnectCallback` 筛地址族 |
| IPv6 可达性 | `Ping` 国内 + 国外各一个已知 IPv6 目标 | 国内用 AliDNS `2400:3200::1`，国外用 Cloudflare `2606:4700:4700::1111` |

**结论分档**

| 状态 | 判定 | 文案 |
|---|---|---|
| 无 IPv6 | 没有全局地址 | 「未启用 IPv6」——中性色，**不算问题**（很多网络本来就只有 IPv4） |
| 有地址但不通 | 有全局地址，国内目标 ping 不通 | **严重** —— 这是最典型的故障：地址分下来了但上游没配好 |
| 只能到国内 | 国内通、国外不通 | 提醒 —— 说明有 IPv6 出口但国际路由缺失 |
| 正常 | 都能通 | 良好，顺带显示 IPv6 出口 IP |

**默认状态是「中性色」而不是「警告色」** —— 没有 IPv6 不是故障，
这一点和 v2.4 立下的「有颜色就必须有问题条目」的规则一致：
无 IPv6 不产生问题条目。

#### 插到索引 2 的代价：`--tab` 的数字含义全部后移

这是本次调整**唯一的破坏性变更**，必须显式处理。

现在的映射：

| `--tab` | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|---|
| 含义 | 概览 | 本机 | 连通性 | DNS | NAT | 路径 | 端口 |

插入 IPv6 后：

| `--tab` | 0 | 1 | **2** | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| 含义 | 概览 | 本机 | **IPv6** | 连通性 | DNS | NAT | 路径 | 端口 |

即 `--tab 3` 会从「DNS」变成「连通性」。

**处理方式：`--tab` 同时接受卡片键，并把键名标为推荐用法。**

```bash
NetCheck.exe --tab ipv6     # 推荐：不随卡片顺序变化
NetCheck.exe --tab 3        # 兼容：数字按新顺序解释
```

理由：`--tab` 用数字本身就绑定了「卡片顺序」这个最容易变的东西，
这次插入正好暴露了它。改成键名是一劳永逸的修法，成本也低（一次 `CardCatalog.CardForKey` 查找）。
数字继续支持，但 `--help` 里把键名排在前面。

**判断依据**：工具版本才 2.4，`--tab` 的数字用法大概率只存在于本项目的 `e2e.ps1` 里
（已确认只有一处 `--tab 5`），破坏成本可忽略。

### 4.4 「端口检测」升级为「连接诊断」

这是高级组里价值最高的一项。现在的 `PortCheck` 已经做了并发 TCP 握手 + banner 抓取，
但它只能回答「通 / 不通」和「握手花了多少毫秒」——**这个粒度定位不到问题**。

**升级思路：把一次访问拆成四段，分别计时。**

```
DNS 解析 ──▶ TCP 建连 ──▶ TLS 握手 ──▶ 首字节 TTFB
   │            │            │             │
 域名→IP      三次握手     证书协商      服务端处理
```

| 阶段 | 测法 | 慢在这一段意味着 |
|---|---|---|
| DNS 解析 | `Dns.GetHostAddressesAsync` 计时（目标是 IP 时跳过） | DNS 服务器慢，或被劫持到了远端 IP |
| TCP 建连 | 现有 `TcpClient.ConnectAsync` 计时 | 网络 RTT 高 / 防火墙丢包 / 目标限速 |
| TLS 握手 | `SslStream.AuthenticateAsClientAsync` 计时 | 证书链拉取慢 / 中间设备干扰 / 算法协商慢 |
| 首字节 TTFB | 发 `HEAD / HTTP/1.1` 后等第一个字节 | **与网络无关**，是服务端处理慢 |

**这张表就是这一项的交付价值** —— 它把「这个网站好慢」这种模糊抱怨，
直接落到一个具体环节上。

**TLS 阶段顺带产出证书信息**（零额外成本，握手时就能拿到）：

- 主体 / 颁发者
- 有效期 + **剩余天数**（< 14 天提醒，过期报严重）
- 是否自签（`Subject == Issuer`）
- 域名是否匹配 —— 由 `SslStream` 的 `RemoteCertificateValidationCallback` 直接给
  `SslPolicyErrors.RemoteCertificateNameMismatch`，不用自己解析 SAN

**保留原有能力**：端口通断判定（开放 / 关闭 / 过滤）、服务名标注、banner 抓取、
并发扫描多端口 —— 一个都不砍，四段耗时只是在「开放」的那些端口上追加。

**默认目标**：`AppSettings.TargetHost` 支持特殊值 `@egress` 并作为默认值。

- 运行时解析成当前出口 IP（复用已有的 `TaskEgressAsync` 结果，没有就先查一次）
- 界面上显示为 `@egress（本机出口 1.2.3.4）`
- 解析不到时（断网）回退 `223.5.5.5` 并在状态栏提示
- **不存 IP 而存 `@egress`** 是因为出口 IP 会变（PPPoE 重播、多出口），存死了下次就是错的

**副作用要写清楚**：这是「从本机看目标端口」，不是「从外部看本机端口」。
本机自扫可能走回环路径**绕过本机防火墙**，所以「关闭」不等于外部也关闭。
卡片说明文字里要加这一句。

**渲染**：四段耗时画一条横向分段条（按时长比例分配宽度，用 `Tone` 着色），
下面列四个数值。这是本次唯一需要新增的渲染元素。

**兼容**：`--check port` 保留为 `connect` 的别名。

### 4.5 新增「暴露面」卡片

**为什么现在可以做了。** 第八节原本写着「不做本机监听端口 / 暴露面，和『端口检测』职责重叠」——
那个判断的前提是端口检测语义模糊。**现在端口检测已经升级为「连接诊断」，方向明确了：**

| | 方向 | 回答的问题 |
|---|---|---|
| 连接诊断 | **outbound** 我去连别人 | 我能不能访问某个服务，慢在哪一段 |
| 暴露面 | **inbound** 看我自己开了什么 | 我有哪些端口在对外听着 |

两者不重叠，是互补的。而且「我刚部署了服务 / 我是不是把数据库暴露了」这个场景，
**inbound 视角才是用户真正想问的**。

**检测内容**

- 枚举本机 TCP 监听：`IPGlobalProperties.GetActiveTcpListeners()`（**纯托管 API，不需要管理员权限**）
- 按绑定地址分两类：

| 类别 | 绑定地址 | 含义 |
|---|---|---|
| **仅本机** | `127.0.0.1` / `::1` | 外部不可达，安全 |
| **对外** | `0.0.0.0` / `::` / 具体网卡 IP | **外部可能可达** ← 重点 |

- 内置**敏感端口清单**，命中「对外」就报警：
  `3306` MySQL · `5432` PostgreSQL · `6379` Redis · `27017` MongoDB ·
  `9200/9300` Elasticsearch · `11211` Memcached · `2375/2376` Docker ·
  `1433` MSSQL · `1521` Oracle · `5984` CouchDB · `3389` RDP · `5900` VNC ·
  `445` SMB · `23` Telnet · `161` SNMP

- **结论**：「有 N 个端口对外监听，其中 M 个是数据库 / 缓存 / 远程控制类服务」

**边界必须写在卡片里**（否则会误导）：

> 这是**本机视角的监听状态**，不等于外网能连上 —— 中间还隔着 NAT 和运营商防火墙。
> 「对外监听」只说明这个端口没有绑回环，不代表它真的从公网可达。

**进程名（哪个程序在听）暂不做** —— 需要 P/Invoke `GetExtendedTcpTable`，
工作量和跨架构风险都不小，先只给「端口 + 服务名」。列入第十一节的候选。

### 4.6 新增「DNS 深度」卡片

现在「DNS」卡片（常用组）测的是**快不快、有没有被劫持**。
这一项测的是**这个 DNS 服务器支不支持现代特性** —— 完全不同的维度。

**检测内容**

| 项 | 方法 | 为什么重要 |
|---|---|---|
| **任意记录类型** | 参数化现有的 `DnsProbe.BuildQuery`（现在写死 `QTYPE=1`），一次全查 A / AAAA / CNAME / MX / TXT / NS | 看 AAAA 有没有 —— 直接决定 IPv6 能不能用 |
| **EDNS0 支持** | 查询里附加 OPT 记录，看响应有没有 OPT | 不支持 = 老服务器，大响应会被截断 |
| **DNSSEC 支持** | 查询置 DO 位，看响应 AD 标志 | 国内运营商 DNS 普遍不支持 |
| **DoH 可用性** | 对已知 DoH 端点发一次查询（如 `https://223.5.5.5/dns-query`） | **国内 DoH 被阻断是高频现象**，而现在的工具完全看不到 |
| **DoT 可用性** | 对 `223.5.5.5:853` 做一次 TCP + TLS 连接 | 同上，853 端口常被干扰 |

**实现要点**（`DnsProbe` 需要扩展的地方）：

- `BuildQuery(domain, type, edns: bool, dnssec: bool)` —— 加 QTYPE、ARCOUNT、OPT 记录
  - OPT 记录：NAME=`0x00`，TYPE=`41`，CLASS=UDP 载荷大小（用 1232），
    TTL 字段的**最高位**就是 DO 位（`0x8000`），RDLEN=0
- `ParseResponse` 从「只认 type==1」扩展为按类型解析，并回传 AD 标志（响应头 byte 3 的 `0x20`）
- 现有调用方（`TestServerAsync` / `DetectHijackAsync`）用默认参数，行为不变

**结论分档**：EDNS0 / DNSSEC / DoH / DoT 各自给「支持 / 不支持 / 被阻断」，
不支持只算**提醒**不算故障（老 DNS 服务器不支持 EDNS0 是正常现象），
但 **DoH / DoT 被阻断**要标出来 —— 这通常意味着网络做了干扰。

**零新增输入**：域名沿用全局目标（若是 IP 则提示「请把目标改成域名」），记录类型全查，特性自动检测。

### 4.7 「高级」组默认收起

首次运行时，`CollapsedCards` 的默认值从空数组变成 `["connect", "path", "expose", "dnsx"]`。

已有用户的配置里没有这几项 → 保持展开（不打扰）。
**只有配置文件不存在时**才写这个默认值 —— 别去覆盖老用户的折叠偏好。

## 五、交互细节

| 场景 | 行为 |
|---|---|
| 点分组标题 | 批量收起 / 展开该组内所有卡片，状态持久化 |
| 组内卡片单独展开 | 允许，分组标题的计数不变（计数是「组内有几项」，不是「展开几项」） |
| 「一键检测」 | **只跑常用组**，不碰高级组（保持现有语义） |
| 概览的问题条目点击 | 若目标在收起的高级组里 → 先展开分组，再滚动到卡片 |
| 命令行 `--tab 7`（端口） | 自动展开「高级」组 |
| 命令行 `--check path` | 正常跑，不受界面折叠影响 |

最后两条是同一个原则的延伸（v2.4 已经确立）：**任何跳转都要让目标可见**。

> 注意 `--tab` 的数字因为插入了 IPv6 而整体后移一位（端口从 6 变成 7），
> 详见 [4.3 的兼容性说明](#插到索引-2-的代价tab-的数字含义全部后移)。

**高级组零新增输入框。** 四项全部复用「检测选项」卡片里的全局目标 / 端口 / 超时：

| 卡片 | 用到的全局参数 |
|---|---|
| 连接诊断 | 目标主机 + 端口表达式 |
| 路径分析 | 目标主机 + 超时 |
| 暴露面 | 无 |
| DNS 深度 | 目标主机（须为域名） |

这样避免了「全局选项」和「卡片内参数」两套输入并存，也就避免了 v2.3 之前
「按钮和内容对不上」那类割裂感重新出现。

## 七、风险与取舍

| 风险 | 应对 |
|---|---|
| 分组标题让界面「多了一层」，反而更复杂 | 标题不套卡片外壳、字号比卡片标题小一号；上线后先看截图再定 |
| **插入 IPv6 让 `--tab` 数字含义整体后移，是破坏性变更** | 同步支持 `--tab <卡片键>` 并把键名标为推荐用法；本项目只有 `e2e.ps1` 一处用到数字，同步改掉；`--help` 里写清楚 |
| 路径每跳 3 次探测，耗时为原来的 3 倍 | 只对**已响应**的跳补足 3 次；无响应的跳立即跳过。同时把最大跳数上限从 30 收到 20，总时长反而可控 |
| 合并 `path` 后，只想单独测 MTU 的用户没入口 | 别名保留；卡片内结果分两段显示，MTU 段单独可见 |
| 连接诊断的 TLS 阶段对非 TLS 端口无意义 | 按端口白名单决定是否做 TLS（443 / 8443 / 465 / 993 / 995 / 636），其余端口跳过并在结果里标注「非 TLS 端口」 |
| TLS 握手在证书有问题时会抛异常，导致整段计时失败 | `RemoteCertificateValidationCallback` 恒返回 `true`（我们只是**观测**证书，不是**验证**连接安全性），把 `SslPolicyErrors` 记下来当结论展示 |
| `@egress` 在断网时解析不到 | 回退 `223.5.5.5` + 状态栏提示，不让检测直接失败 |
| IPv6 在部分机器上探测耗时长（等超时） | 单目标超时压到 1.5 秒，国内国外各一次，总耗时控制在 4 秒内 |
| 「对外监听」被误读为「已暴露在公网」 | 卡片内固定显示那句边界说明，不能只在帮助文档里写 |
| DNS 深度的 DoH / DoT 探测可能被误判为「不支持」 | 区分「连不上」（被阻断）和「连上了但响应异常」（服务端问题），文案分开 |
| 老用户的折叠偏好被覆盖 | 默认值只在配置文件不存在时生效 |
| IPv6 插在中间后，概览卡片的指标卡跳转目标也要跟着改 | 概览的指标卡用的是 `TargetTab` 常量，改常量即可；`ReportViewBuilder` 的索引常量集中在一处，风险可控 |
| v2.6 三项一次性改动较大 | 分 P3 / P4 / P5 三个独立提交，每项单独跑测试；P4 和 P5 无依赖，可并行 |

## 十、「高级」组为什么是这 4 项

### 10.1 先说清扩充的原则

上一轮讨论「2 项是不是太少」时，结论是「数量不是问题，深度才是」。
所以这次扩充**不是往组里塞东西**，而是按两条明确的标准筛：

| 标准 | 说明 |
|---|---|
| **补深度** | 现有项只能回答「通 / 不通」，升级到能回答「问题在哪个环节」 |
| **补盲区** | 有整类问题现在的工具完全看不见 |

四条筛下来只剩两个缺口：**inbound 视角**和**DNS 现代特性**。
所以是「2 项升级 + 2 项新增」，不是「随便加两项」。

### 10.2 每一项对应一个现在看不见的故障

| 卡片 | 升级前的能力 | 升级后能回答的问题 |
|---|---|---|
| 连接诊断 | 端口通不通、握手多少毫秒 | 「这个网站慢」到底慢在 DNS / TCP / TLS / 服务端哪一段？证书还有几天过期？ |
| 路径分析 | 逐跳地址 + 单次延迟 + 路径 MTU | 从**哪一跳**开始丢包？哪一跳是跨网出口？MTU 是不是被隧道压小了？ |
| 暴露面 | —— | 我本机有哪些端口在对外听着？有没有把数据库暴露出去？ |
| DNS 深度 | 解析快不快、有没有被劫持 | 这个 DNS 支不支持 AAAA（能不能用 IPv6）？DoH 是不是被阻断了？ |

### 10.3 明确不做：把 `path` 拆回 `trace` + `mtu` 凑到 5 项

拆回去确实能让计数变成 5，但代价是丢掉 4.2 合并的全部收益 ——
「这一跳慢」和「这一跳 MTU 小」不再在同一个上下文里，
而 MTU 问题恰恰经常出在某条特定隧道上，合并后才能对上号。
**用凑数换掉一个真实的诊断能力，不划算。**

### 10.4 关于计数显示

考虑过把标题右侧的「4 项」去掉，免得把数字摆在眼前。**结论是不去。**

计数是功能性信息 —— 它告诉用户这个组里有没有东西、有几项，去掉之后用户可能根本不点开。
而且 4 项本身已经不显得单薄，没有回避的必要。

## 十一、更远的候选（不进 v2.6）

按「价值 / 成本」粗排，供 v2.7 及以后参考：

| 候选 | 价值 | 成本 | 备注 |
|---|---|---|---|
| 暴露面显示**进程名** | 高（知道是哪个程序在听） | 中（P/Invoke `GetExtendedTcpTable`） | P4 的自然延伸，优先做 |
| NTP 时间偏差 | 中（证书校验失败 / TOTP 失败常源于此） | 低（SNTP 一个包） | 独立卡片 |
| 多目标连通矩阵 | 中（判断「是全网问题还是某站问题」） | 低（复用 ping） | 和「连通性」卡片有部分重叠，要设计好合并方式 |
| TCP 参数诊断（窗口缩放 / 拥塞算法） | 低（偏调优） | 低（`Get-NetTCPSetting`） | 面向特定人群 |
| Wi-Fi 信号质量 | 中 | 高（WlanAPI P/Invoke） | 单独立项评估 |
| 历史趋势 / 持续监控 | 高 | 高（形态变化大） | 属于 v3 |
