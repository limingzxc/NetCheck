# NetCheck（C# / WPF 版）

Windows 桌面网络体检工具。

> 早期有一个 tkinter 写的 Python 版（`nettool.py`），为了「能发给别人」重写成了这个 C# / WPF 版。
> **Python 版已删除**，仓库里只剩这一套实现。下面的对照表保留下来，是因为它记录了选型的理由。

## 一、相比 Python 版的改进

| 方面 | Python 版 | C# 版 |
|---|---|---|
| 分发 | PyInstaller onedir，27 MB 文件夹 | **单文件 exe**，独立版 62.9 MB / 精简版 **478 KB** |
| 启动 | onefile 需解压到临时目录 | 原生 exe，直接启动 |
| 杀毒误报 | PyInstaller bootloader 常被误报 | 明显更低 |
| 获取网卡信息 | 解析 `ipconfig` 文本（GBK 解码 + 中英文标签匹配） | `NetworkInterface.GetAllNetworkInterfaces()` 直接给结构化数据 |
| 长任务 | threading + `root.after` 手动跨线程 | `async/await` + `CancellationToken`，**支持中途取消** |
| 界面 | tkinter | WPF，原生控件、DPI 缩放正确 |
| 分辨率适配 | 手动 | 布局系统自动 |

**最实在的一条**：Python 版里最容易出错的那段代码——GBK 解码、中英文标签双匹配、
DNS 多行续行拼接——在 C# 版里整段消失了。

## 二、功能

### 检测项

| 功能 | 说明 |
|---|---|
| **本机网络配置** | 网卡、IP、掩码、网关、MAC、DNS、速率、DHCP 状态；启动时自动加载 |
| **IPv6** | 全局地址分配（含隐私扩展临时地址识别）、IPv6 出口查询、国内 / 国外目标可达性；**可单独运行** |
| **公网出口 IP** | 原生 UDP(STUN) + HTTP 多服务，两条路径对比，检测多出口/代理；**可单独运行，v2.6 起独立成卡片** |
| **网络延迟 / 丢包 / 抖动** | 探测**网页 / 视频 / 游戏**三类真实服务（不是 DNS 服务器），ICMP 优先、TCP 握手兜底，每项都算抖动与丢包率 |
| **DNS 服务器** | 直接向每个 DNS 发查询测响应速度（不走系统缓存）。**「当前 DNS」（网卡上配的）和「对比 DNS」（公共 DNS，仅作对比）分两段显示**，后者回答「换个 DNS 会不会更快」 |
| **DNS 解析性能** | 逐域名测量系统解析器耗时 |
| **DNS 劫持检测** | 用随机不存在的域名做探针 + 多 DNS 解析结果对比 |
| **NAT 类型** | 4 台 STUN 服务器（国内为主），判定 无NAT / 圆锥型 / 对称型 / 多出口 / 无法判定 |
| **下载带宽** | 多镜像源，默认绕过代理 |
| **路由追踪** | 用 `PingOptions.Ttl` 递增实现，**无需管理员权限** |
| **端口检测** | 批量并发 TCP 握手，含服务名识别与 banner 抓取 |
| **路径 MTU** | DF 二分查找，排查 PMTUD 黑洞 |
| **HTTP / HTTPS 连通性**（v2.6 新增） | 把一次网页访问拆成 DNS → TCP(443) → TLS → HTTP 四层串行探测，**指出卡在哪一层**；默认国内 2 + 境外 1，可追加自定义目标 |
| **导出诊断包** | 报告 + 原始数据 + 系统网络命令输出，打包成 zip；**另有脱敏版**，主机名 / MAC / 公网 IP 打码后再打包 |

### 交互设计

- 打开程序**自动读取本机配置**（纯本地操作，零流量）
- 其余项目由按钮触发，**结果累积显示**，重跑单项不清空其它项
- **一键检测把全部十一项依次跑一遍**（本机配置 → 出口 IP → DNS → 延迟 → 测速 → IPv6 → 网页 → NAT → 路由 → MTU → 端口），
  进度里带 `【3/11】DNS 服务器检测 · …` 的序号，中途可以取消。
  顺序按**诊断链从近到远**排：先看本机、再看出口、再看解析，最后才下探到路径与端口
- **每个公网 IP 右侧都带归属地**（出口 IP、DNS 服务器、路由每一跳），私有地址直接标「局域网」不发请求
- 长任务可**中途取消**（`Esc`）
- **问题条目可以点**：概览卡片里的问题清单是全量汇总，每条都指向一个具体检测项，
  点一下直接跳到那张卡片**并展开它**（跳过去只看到一行标题等于没跳）
- **同一时间只允许一个耗时操作**：检测和诊断包导出互斥（`_busy`），
  期间卡片按钮、工具栏「一键检测」、整个「检测」菜单一起置灰，
  只有「取消当前检测」留着 —— 忙的时候恰恰是它最有用的时候
- **检测参数可调并持久化**：目标主机、网页目标、端口表达式与预设、并发、超时、探测次数……
  改完自动落盘，下次启动原样恢复；卡片折叠状态、窗口尺寸与最大化状态也一并记住。
  填了超出范围的数值会被收敛到边界值并**在状态栏提示**，不再静默跳回
- **可以进脚本**：`--check <名称>` 无人值守跑单项检测，配 `--export` 导出后自动退出
- 导出报告支持 txt / json；导出诊断包为 zip，分**原始**和**脱敏**两版
- 快捷键：`F5` 一键检测、`Esc` 取消、`Ctrl+C` 复制、`Ctrl+S` 导出、
  `Ctrl+B` 诊断包、`Ctrl+Shift+B` 脱敏诊断包
- 目标主机 / 网页目标 / 端口表达式输入框里按**回车**直接执行对应检测

## 三、界面结构

### v2.1：从「一大坨文本」到三层结构

v2.0 的结果区是一大坨滚动文本，11 个区块堆在一起：要滚动才能找到想看的东西，
而且**没有结论**——用户得自己从原始数据里判断网络到底有没有问题。

v2.1 改成「指标卡片 + 结论条 + 分类」三层结构：

- **指标卡片**给结论而不是给数据：`公网出口 = 3 个 / 多出口网络`，而不是列三个 IP 让人自己判断
- **结论条**常驻显示，不切分类也能看到有没有问题
- **问题清单**把异常按「严重 / 注意 / 正常」分级，每条附一句人话解释和影响
- **延迟对比用条形图**而不是纯文本，横向扫一眼就能看出快慢
- **端口用彩色方块**（开放=绿色，关闭=灰色），比 `80/tcp open` 的文本行快得多

### v2.2：从「卡片流」到工具布局

v2.1 的骨架是「顶部标签页 + 居中卡片流」，用起来更像一个展示页而不是工具。
v2.2 换成工具软件的经典布局：菜单栏 / 工具栏 / 左侧导航 / 右侧内容 / 状态栏。

### v2.3：按钮和它要填的展示区合并到一起

v2.2 有个明显的问题：**同一件事出现了两次**。顶部工具栏有「NAT 类型 / DNS / 路由追踪 / 端口检测」，
左侧导航有「NAT / DNS / 路径 / 端口」——内容一样，位置分在两处，
而且点左边的只是切换视图、点上面的才会真的跑检测，用起来很割裂。

v2.3 把两者合成一套：**一个检测项 = 一张卡片，按钮就挂在卡片标题栏上**。

```
┌────────────────────────────────────────────────────────────────────┐
│ 文件(F)  检测(R)  视图(V)  帮助(H)                                  │ ← 菜单栏
├────────────────────────────────────────────────────────────────────┤
│ [一键检测][全部收起]      [取消][复制全文][导出报告][诊断包][脱敏包] │ ← 工具栏（只留全局动作）
├────────────────────────────────────────────────────────────────────┤
│ ── 常用                                        6 项 · 点击收起 ── │ ← 分组标题（整行可点）
│ ┌─ 检测选项  目标 223.5.5.5 · 常用服务（5 个端口）· 并发 64 ──── ▾ ┐ │
│ └──────────────────────────────────────────────────────────────────┘ │
│ ┌─ 概览   公网出口 IP · 网络延迟 · DNS 服务器  [一键检测][出口 IP 检测] ▾ ┐ │

│ └──────────────────────────────────────────────────────────────────┘ │
│ ┌─ 本机网络配置  网卡 · 网关 · DNS · 代理环境变量     [重新读取]  ▾ ┐ │
│ ┌─ IPv6   地址分配 · 出口 · 国内 / 国外可达性          [IPv6 检测] ▾ ┐ │
│ ┌─ 连通性 ①  延迟（网页/视频/游戏）· 下载带宽  [延迟检测][带宽测速] ▾ ┐ │
```

每张卡片的标题栏从左到右是：**标题 · 问题角标 · 说明 · 运行按钮 · 折叠箭头**。
点标题栏（按钮以外的区域）折叠 / 展开，折叠状态记进配置。

卡片流按**常用 / 高级**两组排布，每组前面有一行分组标题（`常用   6 项 · 点击收起`）。
分组标题整行可点，一下收起或展开该组 —— 高级组默认就是收着的。

几个实现上的选择：

- **分组标题刻意用 `Button` 而不是裸 `Border`**：裸 `Border` 在 UIA 里没有 Invoke 模式、
  键盘也 Tab 不到，既没法做自动化验证，也没法用键盘收起整组。
  外观仍然只是一行小字 —— `GroupHeaderButton` 样式把模板换成透明 `Border` + `ContentPresenter`
- **分组不引入第二套折叠状态**：点分组标题就是逐张调 `SetCollapsed`，
  折叠状态仍然只按卡片键存进 `CollapsedCards`。否则「组收起」和「卡片收起」
  两套状态会互相打架
- **首次运行才默认收起「检测选项」和「高级」组**，判据是配置文件**不存在**，不是「配置为空」。
  选项卡展开要占约半屏（12 个输入字段），会把真正该第一眼看到的「概览」挤出首屏 ——
  折叠后标题栏仍然显示配置摘要（目标 / 端口 / 并发），改选项走「视图 → 显示检测选项」或点标题栏。
  老用户的配置里没有这些键，必须保持展开 ——
  不能拿升级当借口替他改折叠偏好。标志位是 `AppSettings.FirstRun`，`e2e` 有专门断言

- **一张卡片可以有多个按钮**：概览同时管一键检测和出口 IP、连通性同时管延迟和带宽、
  路径同时管路由追踪和 MTU，两个按钮并排放在同一张卡片的标题栏上，各自独立
- **拆任务的判据是「卡片能不能自己填满自己」**：如果某个卡片的数据只能靠「一键检测」
  顺带跑出来，它就缺一个独立按钮。按这个判据拆过两次 ——
  延迟拆成 `latency`（否则「连通性」卡片填不满自己），
  出口 IP 拆成 `egress`（否则想看一眼出口就得连带等 DNS 和延迟，约 6 秒，粒度太粗）。
  两次都同时加进了 `--check` 的可选值
- **拆出来的子任务要能独立成立**：`egress` 本身不依赖网卡信息，
  但「有几个出口」的判定要看本机 IPv4 列表，所以它在 `Adapters == null` 时
  会自己补读一次 —— 已经有数据就不重复读。这样无论单独点它、
  还是被 `quick` 调用，行为都一致
- **概览卡片额外挂指标卡和结论条**：它们本来就是全局摘要，
  放进概览卡片比悬在所有内容之上更说得通
- 折叠挂在 `Border.MouseLeftButtonUp` 上。标题栏里嵌了按钮，
  而 `ButtonBase` 自己会吃掉 `MouseLeftButtonUp` 并置 `Handled`，
  所以点按钮不会误触发折叠；代码里还是加了一层「源元素是否在按钮内」的兜底
- 标题栏的 `Background` 必须是 `Transparent` 而不能留空 ——
  背景为 `null` 的 `Border` 不参与命中测试，那样点标题根本折不起来
- `SectionHost` 用 `HorizontalAlignment="Stretch"` + `MaxWidth="1240"`：
  写成 `Center` 会让 `StackPanel` 缩到「内容宽度」，卡片一收起来就变成一条窄条
- 折叠状态按**卡片键**（`options` / `overview` / …）存，不存索引 ——
  以后增删卡片时旧配置不会错位折叠到别的卡片上
- 工具栏只留全局动作，用两列 Grid（左列 `*`、右列 `Auto`）：
  窗口变窄时左列先换行，右侧的「取消 / 导出」始终完整可见
- 窗口尺寸与最大化状态记进配置，下次启动原样恢复

v2.3 还顺手改了两处：

- 延迟探测：**从「测一群 DNS 服务器」改成「按用途测真实服务」**
  （网页 / 视频 / 游戏三类，各带自己的判定阈值）。详见
  [延迟按用途分类](#延迟按用途分类v23)。
- 公网出口 IP 从「一键检测」里拆出来，成了概览卡片上的第二个按钮 ——
  以前想看一眼出口就得连带等 DNS 和延迟（约 6 秒），粒度太粗。

### v2.4：一次设计审查之后的集中修复

v2.3 做完后把 `MainWindow.xaml.cs` / `MainWindow.xaml` / `ViewModels.cs` / `ReportView.cs` /
`Renderer.cs` / `AppSettings.cs` / `CommandLineOptions.cs` 通读了一遍，列出 15 项问题并全部修掉。
下面按「严重 → 中等 → 轻微」记录，因为**每一条都对应一个具体的失效场景**，不是洁癖式重构。

#### 严重：网关会静默消失

这是最隐蔽的一个。四个「顺带需要本机信息」的任务各写了一份补读逻辑，而且**只判断网卡列表**：

```csharp
// 修复前，TaskLatencyAsync
if (s.Adapters == null) { s.Adapters = ...; s.Gateway = ...; }
```

而 `TaskNatAsync` / `TaskDnsAsync` 会设 `Adapters` 却**不设 `Gateway`**。于是：

```
先跑 NAT 或 DNS   → Adapters 被填上，Gateway 仍是 null
再跑延迟检测      → 看到 Adapters != null，整段跳过，Gateway 一直是 null
                  → 连通性卡片里的「本地链路」那一段**整段消失**
```

用户只会觉得「怎么少了一块」，看不出是执行顺序导致的。修复是抽一个统一入口，
条件改成「网卡或网关**任一**为空就补」，两件事各自判空：

```csharp
private static async Task EnsureLocalInfoAsync(DiagState s, CancellationToken ct)
{
    if (s.Adapters != null && !string.IsNullOrEmpty(s.Gateway)) return;
    var adapters = s.Adapters ?? await Task.Run(LocalNetInfo.GetAdapters, ct);
    s.Adapters = adapters;
    if (string.IsNullOrEmpty(s.Gateway)) s.Gateway = LocalNetInfo.PrimaryGateway(adapters);
}
```

`TaskEgressAsync` / `TaskLatencyAsync` / `TaskNatAsync` / `TaskDnsAsync` 四处统一调用它。

#### 严重：概览卡片的角标永远是空的

角标按 `IssueRow.TargetTab == 卡片.TabIndex` 过滤，但**概览卡片就是问题清单本身**，
所有问题的 `TargetTab` 都指向各自的检测项，没有一个指向 `OverviewIndex`。结果：

```
把卡片全收起来时 ——
  连通性 ②  DNS ①  NAT ①      ← 各有一个数字
  概览                         ← 空的，可问题清单就在它里面
```

修复是把概览卡片当特例：它统计**全部**问题，其余卡片仍按 `TargetTab` 过滤。

#### 中等：配色阈值和问题清单阈值是两套数字

| 指标 | 条形/胶囊的阈值 | 问题清单的阈值 | 后果 |
|---|---|---|---|
| 网关延迟 | `3 / 15 ms` | `> 15 ms` | 5 ms 的网关画成**橙色**，清单里却一条都没有 |
| 下载带宽 | `5 / 20 / 100 Mbps` | `< 10 Mbps` | 15 Mbps 转橙但不报 |
| 路径 MTU | `1400 / 1500` | `< 1500` | 1300（红色）只给「注意」 |
| 端口开放 | 橙色胶囊 | 无规则 | 凭空制造焦虑 |

现在所有阈值集中到 `Ui/Thresholds.cs`，**颜色渲染和问题清单调用同一个函数**，
并约定：`Thresholds.IsProblem(tone)` 为真 ⇒ 一定有一条同色调的问题条目，反之亦然。

```csharp
public static Tone Gateway(double ms)
    => ms <= GatewayGoodMs ? Tone.Good
     : ms <= GatewayWarnMs ? Tone.Warn
     : Tone.Bad;
```

顺带补了两条此前「有颜色没解释」的规则：域名解析失败 / 偏慢（`DnsResolve` 条形图一直在上色，
清单里对不上条目）。

`Ui/Thresholds.cs` 不依赖 WPF，所以测试工程能直接引用并断言每档边界与单调性
（见下文「阈值同源」断言组）。

端口开放则统一改成**中性色**（胶囊、概览行、端口页结论条、开放明细值）：扫的端口是用户自己指定的，
「开放」是事实不是问题 —— 保留「对外开放的端口越多，攻击面越大」的说明，但不再给它警示色。

#### 中等：卡片键 ↔ 标签页索引这条映射零测试覆盖

渲染层是 `tabIndex < Tabs.Count ? Tabs[i] : null`，**越界不报错、只是卡片静默变空**。
而这条映射写在 `MainWindow` 里，测试工程引不进来（`MainWindow` 依赖 WPF）。

修复是把卡片的静态定义抽到 `Ui/CardCatalog.cs`（纯数据、不依赖 WPF），测试工程直接引用并断言：

### v2.5：IP 归属地、IPv6 卡片、一键检测补齐

#### 每个公网 IP 右侧显示归属地

出口 IP、DNS 服务器、路由每一跳，凡是有公网 IP 的地方都跟一段归属地
（`223.5.5.5 浙江省杭州市阿里云`、`192.0.2.30 示例 · 荷兰`）。
私有 / 保留网段不打码、也不发请求，直接标「局域网」。

**不单开一列，而是拼进主文本**：归属地长度差异极大（「局域网」4 字 ↔「示例 · 美国 西海岸」11 字），
单开一列要么给最短的那条留一大片空白，要么把最长的截断。拼进主文本后，
键值行用 `Inline Run`（比正文小半号、`Faint` 色），既不影响主信息又不会撑破布局。

两个数据源分工：

| 源 | 支持 | 返回 | 角色 |
|---|---|---|---|
| `whois.pconline.com.cn/ipJson.jsp` | 仅 IPv4 | 中文，含运营商（「浙江省杭州市 电信」） | 首选 |
| `ip-api.com/json/X?lang=zh-CN` | IPv4 + IPv6 | 中文，只有国家 / 省 / 市 | 兜底 |

踩到过、并且已经在代码里防住的坑（**每个都对应一段看起来「能跑通」的错误结果**）：

1. **pconline 拿 IPv6 去问不报错，而是返回查询方自己出口 IP 的归属地。**
   请求 `2408:...` 会得到一个看起来完全正常的中国地址 —— 数据是真的，只是不是这个 IP 的。
   修法是核对响应里的 `ip` 字段与请求的是否一致，不一致就当失败：
   ```csharp
   var got = root.TryGetProperty("ip", out var ipEl) ? ipEl.GetString() ?? "" : "";
   if (!string.Equals(got, ip, StringComparison.OrdinalIgnoreCase)) return "";
   ```
   这也是为什么 IPv6 一律走 `ip-api.com` —— 它是唯一一个真正支持 IPv6 的免费源。
2. **pconline 的响应是 GBK 编码，而 .NET Core 默认不带代码页 936。**
   响应头写的是 `Content-Type: text/html; charset=GBK`，字节实测 `\325\343\275\255`（「浙江」的 GBK）。
   `GetStringAsync` 在 .NET Core 上会直接抛 `ArgumentException`，被 catch 静默吞掉 ——
   表现是「中文接口明明能连通，却永远拿不到运营商信息，每次都悄悄落到备用源」。
   修法两件：静态构造器注册 `CodePagesEncodingProvider.Instance`，
   并且**自己读字节、按响应头声明的 charset 解码**（不再依赖 `GetStringAsync` 的默认解码）：
   ```csharp
   static IpGeo()
   {
       try { Encoding.RegisterProvider(CodePagesEncodingProvider.Instance); }
       catch { /* 极端环境下注册失败也不该让整个模块起不来 */ }
   }

   using var resp = await client.GetAsync(url, cts.Token);
   var bytes = await resp.Content.ReadAsByteArrayAsync(cts.Token);
   return Decode(bytes, resp.Content.Headers.ContentType?.CharSet);
   ```
   `Decode` 是公开的纯函数，测试里用**硬编码的 GBK 字节**（`{0xD6,0xCF,0xB9,0xFA}` = 「中国」）
   断言解码正确 —— 不从 `Encoding.GetEncoding` 现算，否则等于用被测代码验证被测代码。

**查询是批量的、幂等的、可观测的**：`IpGeo.FillAsync(state, ct)` 把状态里所有「还没查过」的 IP
收集起来并发查一遍，结果进 `DiagState.IpLocations` 字典；`PendingCount` 暴露待查数量，
为 0 时不报进度（否则每次点检测都闪一下「正在查询归属地…」）。
各检测任务（出口 / NAT / DNS / 路由）跑完各自调一次，先跑的先把网卡和网关那几个 IP 填上。

**显示规则只有一条，写在 `IpGeo.Of` 里**：查到了就用查到的，私有地址返回「局域网」，
其余返回空串（界面上不显示，而不是显示一个空括号）。「要不要打码」和「要不要发请求」
共用同一套网段判定（`a is 0 or 10 or 127 || a >= 224 || 169.254/16 || 172.16-31 || 192.168/16 || 100.64-127`，
IPv6 补 `fc00::/7`、链路本地、组播、回环），所以不可能出现「打了码却还是发了请求」。

#### IPv6 卡片

按用户反馈「ipv6 显示你好像没做」补上，插在索引 2（本机配置之后、连通性之前）——
它是网络基础能力的一部分，排在本机配置后面最顺。

三个区块：**IPv6 状态**（结论）、**本机 IPv6 地址**（每条带注释）、**可达性**（国内 / 国外各一个目标）。

两个实现要点：

- **临时地址识别**：接口标识符第 9 字节的 **u 位**（`0x02`）置位是固定地址、清零是随机生成的
  隐私扩展地址（RFC 4941）。实测 `2408:8207:...:9c2b:...` 的 `0x9c` 清零，判为临时地址，
  与 Windows `ipconfig` 的结论一致。卡片上会写「全局 · 临时」，用户才知道换个网络它会变。
- **IPv6 出口查询必须强制地址族**：`HttpClient` 默认走 Happy Eyeballs，
  域名有 A 记录时会回退到 IPv4，于是「查 IPv6 出口」查到的是 IPv4 出口 —— 结果看着完全正常。
  修法是在 `SocketsHttpHandler.ConnectCallback` 里自己解析、只挑 IPv6 候选地址：
  ```csharp
  Dns.GetHostAddressesAsync(host, AddressFamily.InterNetworkV6, token)
  ```

结论分五档：双栈正常 / 有地址但完全不通 / 只能访问国内 / 未启用 IPv6。
**「没有 IPv6」刻意不产生问题条目** —— 多数网络只有 IPv4，这不是故障，
把它列进「问题与提示」会让每次体检都挂着一条假警报。

#### 一键检测跑全部十一项

见下文「[`all` 只展开原子检测项](#all-只展开原子检测项不包含-quick)」——
界面上那份手写的 4 项展开表已经删掉，改成直接读 `CommandLineOptions.AllExpansion`。
进度文案带上序号（`【3/11】DNS 服务器检测 · …`），用户能看到「还剩几项」。

### v2.6：按一份功能评审重组分类与补齐缺口

改动来自一份外部功能评审（「功能设置建议」）。评审的核心判断是：**这个工具的问题是「功能没归类」，
不是「功能不够多」** —— 所以这次既补了缺口，也明确划了不做的东西。

#### 卡片层次重排

十张卡片重新分了两级。一级分组决定「默认视野」，二级分组只用在高级区：

```
常用（默认展开，6 张）
  检测选项 · 概览 · 本机网络配置 · 公网出口 IP · 连通性 · DNS

高级（默认收起，5 张）
  网络路径  ├ 路径（逐跳路由 · 路径 MTU）
  连接能力  ├ NAT 类型        ├ 端口
  协议      ├ IPv4 / IPv6     └ HTTP / HTTPS
```

三处挪动，都是评审提的：

- **IPv6 从「常用」挪进「高级 · 协议」**，标题也改成「IPv4 / IPv6」。
  此前按用户反馈「IPv6 卡片应该靠前」把它插在了索引 2 —— 那是针对「IPv6 显示好像没做」的补救，
  现在它已经完整实现了，再占着常用区第二位就是在挤占日常体检的视野。
  协议层的东西放在「协议」这个二级分组下，语义比位置更重要。
- **NAT 类型从「常用」挪进「高级 · 连接能力」**。它和端口是同一类问题（连接能不能建立起来），
  放在一起用户不用自己归纳；而且 NAT 检测依赖 UDP，在限制 UDP 的网络里会长时间超时，本来就不适合日常跑。
- **公网出口 IP 从概览里拆成独立卡片**。以前想单独重查一次出口，就得把整个概览重跑一遍。

二级分组的标题**刻意不可点**：折叠状态只按卡片键存一套，
再加一层「组收起」的状态会和「卡片收起」互相打架（一级分组标题是可点的，那里逐张调 `SetCollapsed`）。

#### 补齐的五个缺口

| 补的东西 | 为什么 |
|---|---|
| **丢包率** | 延迟只回答「快不快」，丢包回答「稳不稳」。原先把丢包塞在延迟目标的备注里，概览上看不到 |
| **抖动** | 同上。视频会议和游戏对抖动比对平均延迟敏感得多 |
| **IPv6** | 上一版已经做了，这次只是把它归到「协议」组 |
| **HTTP / HTTPS 分级连通性** | 见下 |
| **网关连通性** | 「连通性」卡片顶部现在有一段「网络质量」：网关 / 延迟 / 抖动 / 丢包。网关这一跳不通，后面所有目标都不用看了 |

**HTTP / HTTPS** 是这次唯一一个全新检测项。它把一次网页访问拆成
DNS → TCP(443) → TLS → HTTP 四层**严格串行**跑，第一层失败就停：

```
DNS   11 ms   110.242.68.66 · 共 2 条记录
TCP   9.0 ms  110.242.68.66:443
TLS   34 ms   Tls13 · 证书 2027-01-08 到期
HTTP  41 ms   HTTP/1.1 200 OK
```

**「卡在第几层」本身就是结论。**「能解析但连不上」和「连上了但 TLS 失败」是两种完全不同的问题
（前者多半是目标或链路，后者常见于证书、中间设备干扰、系统时间不对），
只说「网站打不开」对排查毫无帮助。所以失败的目标段标题直接写成「卡在 TCP 层 · TCP 连接建立失败」，
下面只渲染**跑过的那几步** —— 没跑到的层不显示，避免用户以为「TLS 也失败了」。

三个实现上的选择：

- **用裸 socket 而不是 `HttpClient`。** 后者把 DNS、连接、TLS、HTTP 全揉在一起，
  失败了只给一句「连接被关闭」—— 而这正是本项要回答的问题。
- **目标之间并行跑，单个目标内部串行。** 每个目标最坏 2+3+3+3 = 11 秒，
  串行 4 个目标就是 44 秒，用户会以为程序卡死了。
- **证书走默认校验。** 证书过期 / 域名不匹配本身就是体检要发现的问题，放行等于把它藏起来。

目标默认是**国内 2（百度 / 腾讯网）+ 境外 1（Cloudflare）**。境外那个不通本身就是有用信息 ——
它回答「这台机器能不能上外网」。自己填的目标追加在后面（`AppSettings.WebTarget`，默认留空）。

> 网页目标**只收纯 ASCII 域名**，`WebProbe.TryParseTarget` 刻意拒绝两类输入：
> **裸 IP**（本项要跑 TLS，握手要靠 SNI 送域名、证书也要按域名校验；拿 IP 去连服务端多半给一张默认证书，
> 校验失败后报出来的是「TLS 握手失败」，把「你填错了目标」伪装成「你的网络有问题」—— 测 IP 该用「端口检测」）
> 和**非 ASCII 域名**（如 `例子.测试`，真实握手需要先转 Punycode，与其在内部悄悄转码、让用户不知道
> 到底测了哪个域名，不如拒绝并让用户填 Punycode 形式）。
> `--web` 命令行参数用的是同一个解析器，保证「命令行接受的」和「探测时能用的」是同一套规则。

#### DNS 卡片：把「当前 DNS」和「对比 DNS」分开

评审第 5 条。原文是「尤其是『当前 DNS』和『实际对比 DNS』分开，会比增加 DNSSEC 之类的功能
更符合你这个工具的定位」—— 也就是**不动检测能力，只动信息组织**。

原先卡片里只有一段「系统 DNS 服务器」（网卡上配的那几台），
而公共 DNS 只出现在「DNS 劫持检测」和「多服务器解析对比」里，且只报结论、不报耗时。
结果是：用户知道自己的 DNS 是 38 ms，但**没有任何信息告诉他这是快还是慢**。

现在卡片分成五段，前两段是「现状」，后两段是「备选」：

```
当前 DNS        ← 网卡上配的，含解析耗时 + 归属地
域名解析耗时     ← 本机解析器逐域名
DNS 劫持检测     ← 结论 + 逐服务器
对比 DNS        ← 公共 DNS 的耗时（新增）
多服务器解析对比  ← 同一域名在各 DNS 上的结果差异
```

`DnsProbe.TestCompareServersAsync` 是这次唯一的新探测：对 `CompareServers` 那四台
（223.5.5.5 / 119.29.29.29 / 114.114.114.114 / 8.8.8.8）各测一次响应耗时，服务器之间并行跑。
结果存进 `DiagState.DnsCompareTests`，和 `DnsServerTests` **刻意分开** ——
前者是「你正在用的」，后者是「你可以换的」，混在一个列表里界面就没法把这两件事分开讲。

三个实现上的判断：

- **两边必须用同一个域名测**（`DnsProbe.CompareTestDomain`）。换个域名，解析条数、
  有没有命中 CDN 边缘、有没有被缓存都会变，差个几十毫秒很正常 ——
  那时候「我的 DNS 比阿里 DNS 慢 30 ms」就成了一个由测量口径不一致造出来的假结论。
- **局域网地址不参与比较。** 当前 DNS 是 `192.168.1.1` 时它的 0.5 ms 只代表
  **到路由器的往返**，不含路由器往上递归的时间。拿它去比会得出「公共 DNS 慢 14 倍」这种假结论，
  所以这一段会明说「这两个数字不能直接比」，而不是硬给一个结论。
- **对比段刻意不按绝对阈值上色。** 这些服务器用户并没有在用，
  给它们标红等于报一个「用户修不了的故障」；8.8.8.8 在国内慢本来就是常态，
  不是本机网络的问题（和「境外网页目标失败降级」是同一条理由）。
  这一段要回答的是「换一个会不会更快」，所以颜色表达的是**相对排序** —— 只把最快的那台标绿。

`Thresholds.DnsSwitchGainMs` / `DnsSwitchGainRatio` 是「值得换」的判据：
要**同时**快够 15 ms 和快够一倍才给一句建议（只看绝对差值会把「2 ms vs 1 ms」也算成值得换）。
判据封装在 `Thresholds.DnsSwitchWorthIt` 里，**卡片结论条和问题清单共用同一个函数** ——
两边各写一套比较逻辑，迟早会漂移成「结论条是橙色、清单里却找不到解释」。

值得换时结论条给橙色（`Warn`），于是按「橙色 ⇒ 必有问题条目」这条不变式，
问题清单里就**必须**有一条对应的「可以换个更快的 DNS（省 N ms）」，点进去跳回 DNS 卡片。
（初版这里只给颜色、不给条目 —— 用户看到橙色却在清单里找不到解释，正是 `Thresholds.cs`
开头说的那类「口径裂缝」。）

#### 同一份数据，一张卡片里不能有两种颜色

改完上面那条后，又发现同一个失败在 DNS 卡片里被画成了两种颜色，一起修掉：

| 位置 | 原来 | 现在 | 理由 |
|---|---|---|---|
| 劫持检测 → 公共 DNS「无响应」 | 橙色 `Warn` | **中性灰** `Neutral` | 这些是用户没在用的公共 DNS，标橙等于报一个他修不了的故障；而且同一台在同一张卡片的「对比 DNS」段里本来就是灰的，自相矛盾 |
| 劫持检测 → 结论文案 | 「**所有服务器**对不存在的域名都正确返回 NXDOMAIN」 | 「未发现劫持（3/4 台正常应答，8.8.8.8 无响应）」 | `AnyHijacked` 在服务器**超时**时也是假，于是原句会在明明有服务器没应答时宣称全都正常。现在按实际应答台数说，并且**不给绿色**（只验证了 3 台，没法定论） |
| 劫持检测 → 一台都没有 | 同上，会宣称「所有服务器」都正常 | 「没有可用于探测的 DNS 服务器」（中性） | 空列表时「所有服务器都正常」是句空话 |

「结论文案必须与数据一致」和「橙色 ⇒ 必有问题条目」是同一类要求的两面：
**界面上的每一句话、每一种颜色，都要能追溯到具体数据。** 这三条都补了单元断言。

#### 明确不做的东西
评审列了一批「工具箱化」功能，这次**全部没做**，理由记在这里免得下次又有人提：

| 不做的 | 理由 |
|---|---|
| Wi-Fi 信号强度 / 信道 | 和「网络通不通」是两件事，属于无线勘察工具 |
| ARP 表 / 邻居发现 | 只在排查局域网内冲突时有用，日常体检里是纯噪音 |
| DHCP 租约信息 | 同上，而且 Windows API 拿到的信息本来就残缺 |
| 全端口扫描 | 变成扫描器了，会被杀软拦、被运营商封 |
| Whois / ASN / CDN 检测 | 查资料而不是测网络，浏览器更快 |
| 真实外网端口探测 | 需要公网回连服务，做不了普适 |

评审另外确认了一件事：**「启动只自动读本机配置、其他手动」的策略是对的，不要改。**
带宽测速消耗流量、NAT 依赖 UDP 可能长时间超时，这些都不该在打开程序时就跑。

#### 两个细节修正

- **`Thresholds.Loss` 补了零档**：原来只有「≥ X% 算严重、其余算提醒」两档，
  于是 **0% 丢包会被画成橙色**。现在是 `percent <= 0 → 绿`。
- **丢包取「最差目标」而不是「代表目标」**：延迟、抖动取代表值是合理的（它们描述「这条路径有多快、稳不稳」），
  但丢包是**故障指示器** —— 只要任何一条路径在丢包，网络就已经有问题了。
  按代表目标取会出现「百度 0% → 概览显示 0.0%」，而游戏路径实际在丢 8%，
  概览恰恰在最该报警的时候报了平安。所以取最大值，并用 Sub 行标明是谁在丢。


### 检测选项（v2.2 新增，v2.3 改成卡片）

以前的参数是写死的常量：端口固定 `22,80,443,3389,8080`、并发固定 64、超时固定 1500 ms、
延迟固定 4 次。现在全部可以在最上面那张「检测选项」卡片里调，改完自动落盘。
卡片折叠起来后，标题栏仍会显示一行当前配置摘要（`目标 223.5.5.5 · 常用服务（5 个端口）· 并发 64`）：

| 选项 | 范围 | 说明 |
|---|---|---|
| 目标主机 | — | 路由追踪 / MTU / 端口检测共用（**回车 = 立即路由追踪**） |
| 网页目标 | — | HTTP / HTTPS 检测的自定义目标，留空就不测（**回车 = 立即网页连通性检测**）。只收纯 ASCII 域名，裸 IP 与非 ASCII 域名会被清空 |
| 端口预设 | 10 组 | 默认目标（公共 DNS）/ 常用服务 / Web / 数据库 / 远程管理 / 邮件与文件共享 / 公网危险暴露 / 常见高危 20 个 / 1-1024 全量 / 自定义 |
| 端口表达式 | — | 逗号 / 空格 / 分号分隔，支持 `8000-8010` 范围写法（**回车 = 立即端口检测**） |
| 端口并发数 | 1 ~ 512 | 过高可能被防火墙判定为扫描 |
| 端口超时 | 100 ~ 15000 ms | 内网可调小，跨公网建议 1500 以上 |
| 延迟探测次数 | 1 ~ 20 | 次数越多抖动数据越准，耗时线性增长 |
| 路由最大跳数 | 1 ~ 64 | — |
| 路由单跳超时 | 200 ~ 5000 ms | 跨公网跳数多、丢包重时调大 |
| 测速时长 | 3 ~ 60 秒 | — |
| DNS 超时 | 300 ~ 10000 ms | 公共 DNS 通常 2500 足够 |

端口表达式下方有实时提示：解析出的端口数 + 按当前并发与超时估算的最坏耗时
（`默认目标（公共 DNS） · 共 3 个端口 · 最坏约 0.1 秒`），填错时直接变红并说明原因。

**默认端口要跟默认目标配套**（v2.4）：默认目标是 `223.5.5.5`（一台公共 DNS），
它上面 53 / 80 / 443 是开放的、22 / 3389 / 8080 一定关闭。
以前默认给「常用服务」那串，用户第一次点端口检测就看到两个「关闭」，会以为工具坏了。
现在 `AppSettings.PortSpec` / `PortPreset` 的默认值和 `Clamp` 的回退值
统一取自 `PortPresets.DefaultSpec` / `DefaultName`，只有一处来源。

**预设反查用集合比对**：`MatchName("8080,3389,443,80,22")` 要能认出「常用服务」。
直接比字符串会因为顺序和空格不同而认不出来，所以两边都先过一遍 `ParsePorts`
再比排序后的端口列表。

**所有数值都过 `Clamp()`**：手改配置文件把并发填成 99999 也不会把程序卡死。
读取时和保存前都收敛一次。

### 命令行参数（v2.2 新增，v2.3 补 `latency` / `egress`，v2.5 补 `ipv6` 与 `--tab` 键名，v2.6 补 `web` / `--web`）

工具软件的另一个标志是能进脚本。`--check` 可以无人值守地跑单项检测：

```bash
NetCheck.exe --help
NetCheck.exe --check port --host 223.5.5.5 --ports 53,443 --export r.json
NetCheck.exe --check egress --export ip.json     # 只查公网出口 IP，约 2 秒
NetCheck.exe --check ipv6 --export v6.json       # 只查 IPv6 地址、出口与可达性
NetCheck.exe --check web --export web.json       # 只跑 DNS→TCP→TLS→HTTP 分级探测
NetCheck.exe --check web --web example.com/path --export web.json   # 追加一个自定义目标
NetCheck.exe --check all --export full.json
NetCheck.exe --host 8.8.8.8 --ports 53,443 --auto --export report.txt
NetCheck.exe --tab path --ports 1-1024           # 滚动到「路径」卡片
NetCheck.exe --tab web --ports 1-1024            # 键名写法，等价于 --tab 9
```

| 参数 | 说明 |
|---|---|
| `--host <主机>` | 覆盖配置里的目标主机（路由 / MTU / 端口的**探测对端**，通常是 IP） |
| `--web <域名>` | 覆盖配置里的**网页目标**，可带协议头与路径（`example.com` / `https://example.com/a`）。只收纯 ASCII 域名，裸 IP 与非 ASCII 域名会被拒绝 |
| `--ports <表达式>` | 覆盖端口表达式，并自动反查对应的预设名 |
| `--tab <键名 \| 0-9>` | 启动后滚动到某张卡片。**推荐用键名**：`options` / `overview` / `local` / `egress` / `link` / `dns` / `path` / `nat` / `port` / `ipv6` / `web`；数字写法按当前顺序 0~9 兼容保留 |
| `--check <名称>` | `local` / `quick` / `egress` / `dns` / `latency` / `speed` / `ipv6` / `web` / `nat` / `trace` / `mtu` / `port` / `all` |
| `--auto` | 等价于 `--check quick` |
| `--export <路径>` | 按扩展名决定 txt / json；配合 `--check` 时导出完**自动退出** |
| `--help` | 弹说明后退出 |

`--key value` 与 `--key=value` 两种写法都支持。参数解析**不抛异常**，
无法识别的项收集到 `Errors` 里由界面统一提示——命令行写错了不该让程序崩。

**`--web` 和 `--host` 是两个参数**，不是同一个：`--host` 是路由 / MTU / 端口检测的探测对端
（通常是 IP，不需要域名），而网页目标必须是一个域名 —— 两项的合法取值没有交集，
合成一个参数只会让两边都变得难解释。`--web` 的校验直接调 `WebProbe.TryParseTarget`，
**不另写一份**，否则「命令行接受了一个探测时用不了的域名」这种错会一直存在。

#### `--tab` 为什么从数字改成键名

`--tab` 一开始收的是标签页索引（`--tab 6`）。卡片顺序一动，这个数字的含义就变了 ——
本批把 IPv6 卡片插到索引 2，原本指向「路径」的 `6` 变成了「端口」，**而且不报任何错**，
只是滚到了另一张卡片上。凡是「写进脚本的东西会被无声改变语义」，都该改成不随顺序漂移的写法。

现在 `--tab` 优先认卡片键名（`--tab ipv6`），数字仍然接受、按当前顺序解释，帮助文本里两个都列。
校验分两层：`CommandLineOptions` 只做**形状校验**（首字符必须是字母，其余字母 / 数字 / 连字符），
「这张卡片到底存不存在」交给 `CardCatalog.CardForKey` 判定 ——
不存在的键名不报错、照常开主窗口，因为卡片增删是正常的版本演进，
拿旧脚本去跑新版本不该弹一个错误框。`--tab 1x`（首字符是数字）会被形状校验挡下，
否则它既不是合法索引也不是合法键名，静默落到「不滚动」最难排查。

#### `all` 只展开原子检测项，不包含 `quick`

`--check all` 的展开表抽到了 `CommandLineOptions.AllExpansion`，而不是写死在界面代码里 ——
这样单元测试能直接断言它，否则「新增检测项却忘了加进 all」这种疏漏没有任何东西能挡住。
**界面上那个「一键检测」按钮走的就是同一份表**，不再各自维护一遍。

```csharp
// local 必须最前：后面几项都要用网卡信息。
// 顺序按诊断链从近到远排：本机 → 出口 → DNS → 延迟 → 带宽 → IPv6 → 网页 → NAT → 路由 → MTU → 端口。
// 顺带一个性质：前四项恰好等于 quick 的展开，所以 all 里再放 quick 一定是重复劳动。
public static readonly string[] AllExpansion =
    { "local", "egress", "dns", "latency", "speed", "ipv6", "web", "nat", "trace", "mtu", "port" };
```

**不含 `quick`** 是刻意的：`quick` 是 `local + egress + dns + latency` 的预设，
把它也放进展开表会让这四项各跑两遍，白白多花将近一半时间。
`all` 的语义是「每个原子检测项各跑一遍」，`quick` 是个预设、不是原子项。

配套有五条单元断言守着这个不变式：展开表无重复、每一项都是合法的 `--check` 值、
**反向覆盖** —— `CheckNames` 里除 `quick`/`all` 外的每一项都必须在展开表里恰好出现一次、
展开表长度恰好等于 `CheckNames.Length - 2`，
以及**前四项恰好等于 `quick` 的展开**（把「quick 是这四项的预设」这句话变成可执行的断言）。
长度那条最要紧，它是唯一能挡住「加了新检测项但忘了加进 `all`」的东西。

> 「一键检测并没有触发所有检测」这个 bug 就是这条不变式被破坏的结果：
> 界面上那份展开表是手写的、只列了 4 项，而 `AllExpansion` 已经涨到 9 项，
> 两者谁也没管谁。现在界面直接读 `AllExpansion`，**同一个事实只有一处来源**。

| 键 | 动作 |
|---|---|
| `F5` | 一键检测 |
| `Esc` | 取消当前检测 |
| `Ctrl+C` | 复制完整报告（焦点在输入框里时让给系统的文本复制） |
| `Ctrl+S` | 导出报告 |
| `Ctrl+B` | 导出诊断包 |
| `Ctrl+Shift+B` | 导出诊断包（脱敏） |

`Ctrl+C` 的例外判断很有必要：不看焦点就抢 `Ctrl+C`，用户在「目标主机」框里
复制一个 IP 时会发现剪贴板里变成了整份报告。

`Ctrl+B` 和 `Ctrl+Shift+B` 共用同一个 `case Key.B when ctrl`，在分支里按 `shift` 分流。
不把 Shift 写进 `when` 条件是为了让两者走同一处 —— 否则要么写成两个 case（重复），
要么写成 `when ctrl && !shift` + `when ctrl && shift`（更容易漏掉一个）。

### 条形图的量程处理

`BarRow.Scale()` 有两个必须注意的地方：

1. **不能设绝对量程下限**。最初的实现是 `max(100ms, 最大值×1.1)`，
   结果全是几毫秒的 DNS 测速被压成一根根小牙签——所有条都贴着最小值。
   正确的做法是纯相对量程 `最大值×1.1`，让最长的那条几乎占满轨道。
2. **量程跨度超过 20 倍时改用平方根压缩**。DNS 卡片里本地运营商 DNS 0.5 ms、国外 DNS 73 ms，
   线性缩放下本地那条会被压成看不见的一个点。开方后 0.5 ms 也能有 10 px。
   此时条长只表示量级，界面上会明确写出来（"条形按平方根压缩（只表示量级）"）。

> 延迟卡片不存在这个问题：本地网关单独一段、三类服务各自分组，
> 每组内部的跨度都在 10 倍以内（实测游戏组 8 ms ~ 73 ms）。

### 延迟按用途分类（v2.3）

v2.3 之前延迟探测的目标是**一群 DNS 服务器**（阿里 223.5.5.5、114、1.1.1.1、8.8.8.8……）。
这有两个问题：

1. **DNS 服务器不是用户用的服务**。用户关心的是「能不能流畅刷网页、看视频、打游戏」，
   而不是「到某个递归解析器的往返时间」。两者路径常常不一样 ——
   DNS 可能被运营商就近拦截应答（0.5 ms），真实服务的 CDN 边缘节点却在几十毫秒外。
2. **一个阈值打天下**。以前所有目标共用「≤50 ms 良好」这一把尺子，
   结果国内 8 ms 的腾讯游戏和 73 ms 的 Steam 被塞进同一个判定里，
   而实际上「8 ms 打游戏」和「73 ms 刷网页」都完全够用 —— 阈值必须跟着用途走。

现在按三类真实服务探测，每类三个目标，各带自己的判定阈值：

| 分类 | 目标 | 良好 | 可用 | 为什么是这个阈值 |
|---|---|---|---|---|
| **网页浏览** | 百度 `www.baidu.com`<br>淘宝 `www.taobao.com`<br>腾讯网 `www.qq.com` | ≤100 ms | ≤250 ms | 打开网页、刷新、搜索；100 ms 完全无感 |
| **在线视频** | 哔哩哔哩 `www.bilibili.com`<br>爱奇艺 `www.iqiyi.com`<br>腾讯视频 `v.qq.com` | ≤120 ms | ≤300 ms | 起播与拖动进度条（缓冲更看带宽，所以阈值比网页略宽） |
| **游戏** | 腾讯游戏 `game.qq.com`<br>网易游戏 `game.163.com`<br>Steam `store.steampowered.com` | ≤50 ms | ≤100 ms | 实时对战，对延迟最敏感；100 ms 已能明显感觉到操作滞后 |

几个设计上的选择：

- **目标是域名，不是 IP**。域名会解析到 CDN 边缘节点，测出来的是「到最近的服务节点有多远」，
  这才是用户实际走的那条路；写死 IP 反而会测到一个未必服务你的节点。
- **国内和境外平台放同一组**。游戏类里 Steam 通常比国内平台高一个数量级（实测 73 ms vs 8 ms），
  放在一起对比才有意义 —— 一眼就能看出「问题出在到这一家的路径上，不是整条宽带不行」。
- **ICMP 通了就不再跑 TCP**。目标从 5 个涨到 9 个之后，原先「两种都跑、最后只留一个」的写法
  会白白多花一倍时间。ICMP 最接近链路真实延迟，通了就用它；不响应才退到 TCP 握手。
- **判定按类出结论，每类最多一条**。用户想知道的是「能不能流畅刷网页 / 看视频 / 打游戏」，
  而不是 9 个目标各自的数字，所以每类只出一条 ——
  「游戏整体延迟偏高（最快 腾讯游戏 8.1 ms）」或「游戏有目标延迟偏高（Steam 72.9 ms）」，
  后者还会补一句「问题出在到这一家的路径上」。
- **展示按分类分组**，每组用自己的量程画条形图，
  这样「游戏里 Steam 明显比别人慢一截」一眼就能看出来；
  本地网关单独一段 —— 它是唯一一个「应该低于 3 ms」的目标，和公网目标放同一把尺子上会被压成看不见的一条线。
- **分类对不上的目标不吞掉**。旧版本导出的 json、手工构造的目标会归到「其他目标」一段照常显示。

### 延迟卡片的代表值

概览卡片上那个「网络延迟 X ms」优先取 **网页浏览** 类里 ≥2 ms 的最小值。

两个理由：

1. 取全局最小值会取到本地缓存或运营商拦截的应答（0.5 ms），根本没出网，
   会得出「网络延迟 0.5 ms」这种没有意义的结论。
2. 网页浏览是最普遍的使用场景，拿它当「这台机器的网络延迟」最贴近用户直觉；
   游戏类的阈值更严，拿它当代表值会显得整体偏慢。

网页浏览类没有可用目标时才退回全部目标里取。

### 细节打磨

这些都是在最小窗口（960×640）下截图逐项检查时发现的，不看一眼根本不会发现：

| 问题 | 处理 |
|---|---|
| 结论条 8 个胶囊，窄窗口下折成两排 | 卡片已经显示了出口数/延迟/带宽/NAT，结论条**只留卡片上没有的**（劫持、网关、MTU、开放端口），减到 4 个正好一行 |

## 四、运行与分发

### 开发运行

```bash
cd NetCheckCSharp
dotnet run
```

### 发布

最省事的方式：**双击项目根目录的 `build.bat`** —— 出两个版本，产物在 `publish/`，每个版本一个单文件 exe。

```bat
build.bat                :: 两种都出
build.bat standalone     :: 只出独立版
build.bat lite           :: 只出精简版
build.bat help           :: 用法
```

等价的 Python 版（**中文输出**，参数写法不同）在 `NetCheckCSharp/build.py`：

```bash
cd NetCheckCSharp
python build.py              # 两种都出
python build.py --standalone # 只出独立版
python build.py --lite       # 只出精简版
```

> `build.bat` 里的每一个字节都是 ASCII，连注释都是英文。
> cmd.exe 是按当前 OEM 代码页解析 .bat 的，还会在运行中按字节偏移回读文件 ——
> 在别的语言环境下中文会变乱码，某个字节错位甚至会让整个脚本不执行。
> 想读中文说明就用 `build.py`，两者产物完全一致。

| 版本 | 体积 | 适用场景 |
|---|---|---|
| `NetCheck-standalone` | 62.9 MB | **目标机器可能没装 .NET** → 用这个，双击即用 |
| `NetCheck-lite` | **478 KB** | 确认对方装了 .NET 8 桌面运行时 → 体积几乎可以忽略 |

> 精简版小到 478 KB 是因为只打包了程序本身，运行时由系统提供。
> 如果对方没装，双击不会有任何反应（这是最容易踩的坑），所以不确定时一律用独立版。

**① 单元测试（不碰网络，约 0.5 秒）**

## 六、实现要点

### NAT 判定必须复用同一个 UDP socket

```csharp
using var udp = new UdpClient(new IPEndPoint(IPAddress.Any, 0));
report.LocalPort = ((IPEndPoint)udp.Client.LocalEndPoint!).Port;
foreach (var obs in await QueryAllAsync(udp, ct))   // 并发，但共用同一个 udp
    report.Observations.Add(obs);
```

每次新建 socket 会导致源端口不同，把所有网络都误判成对称型 NAT。
共用 socket 时还要按**事务 ID** 匹配响应，否则会串包。

### STUN 服务器要选国内能直连的

判定 NAT 类型靠的是**比较**：同一本地端口在不同目标下映射到的外部端口是否一致。
所以至少要有两台服务器回应，一台都不通就只能报「未知」。

把服务器全押在境外，网络稍有风吹草动就一台不剩。早先的列表是
`stun.l.google.com` / `stun1.l.google.com` / `stun.cloudflare.com` / `stun.qq.com` ——
四台里三台境外，而且实测下来 **`stun.qq.com` 已经不再响应了**。现在换成：

| 服务器 | 实测 | 说明 |
|---|---|---|
| `stun.douyucdn.cn:18000` | 28 ms | 斗鱼 |
| `stun.hitv.com:3478` | 32 ms | 芒果TV |
| `stun.chat.bilibili.com:3478` | 35 ms | B站 |
| `stun.cloudflare.com:3478` | 212 ms | 只作补充，连不上也不影响结论 |

前三台是国内大厂的公共服务，不依赖任何境外链路。
**顺序有意义** —— 出口 IP 探测按这个顺序逐个试、第一个成功就返回。

### 查询要并发，不能串行

串行 `foreach` 的问题是：只要有一台服务器被拦掉，就要为它单独等满一个超时。
四台里三台不通就是九秒起步，而用户只是想知道自己的 NAT 类型。
现在并发发出全部请求、共用一个 socket，再按事务 ID 分发响应，
总耗时只取决于最慢的那一台。

### 样本不足时必须说「无法判定」，不能猜

圆锥型和对称型的区别，看的是**同一本地端口在不同目标下映射到的外部端口是否一致** ——
只有一个目标就无从比较。

早先的判定顺序是这样的：

```csharp
else if (r.MappedPorts.Count == 1)   // 只有一台回应时，这里同样成立
    r.Type = "圆锥型 NAT（Cone）";
```

只有一台服务器回应时 `MappedPorts.Count` 也是 1，于是直接落进「圆锥型」分支 ——
把「没测出来」当成了「测出来是好的」，而圆锥型恰好是「好消息」，
等于默默给了用户一个假的绿灯。现在中间插了一道 `ok.Count < 2` 的护栏，老实报「无法判定」。

### 路由追踪不按具体枚举值分支

TTL 超时在不同平台/版本上返回 `IPStatus.TimeExceeded` 或 `IPStatus.TtlExpired`，
且此时 `RoundtripTime` 常为 0。用三分法更稳：

```csharp
if (reply.Status == IPStatus.Success) { /* 到达 */ }
else if (reply.Status == IPStatus.TimedOut || reply.Address == null) { /* 超时 */ }
else { hop.Ms = sw.Elapsed.TotalMilliseconds; /* 中间跳，必须用秒表计时 */ }
```

### HttpClient 必须带 User-Agent

.NET 默认不发 UA，国内镜像站会直接返回 **403**，导致测速全部失败。
这个坑很隐蔽，因为错误信息只有 "HTTP 403"。

### 脱敏导出：脱什么、留什么

诊断包的用途本来就是**发给别人** —— 发给运维、贴到论坛求助。可原始包里装着
主机名、MAC、公网出口 IP、ARP 邻居表、带进程号的活动 TCP 连接，
这些凑在一起足以定位到「哪台机器、哪条宽带」。用户点导出的时候未必想到这一层，
等贴到论坛上再后悔就晚了。

判断标准只有一条：**这条信息能不能定位到具体的人**。能，就打码；
不能而且诊断离不开它，就原样保留。

| 内容 | 处理 | 理由 |
|---|---|---|
| 主机名 | → `HOST-***` | 主机名经常带姓名或公司缩写 |
| MAC 地址 | 留 OUI（前三段），后三段打码 | OUI 只说明网卡厂商，后三段才是设备唯一标识 |
| 公网 IPv4 | 留前两段，后两段打码 | 前两段是运营商和地域，后两段才是这一条线路 |
| 私有 IPv4 | **原样保留** | 192.168 / 10. / 172.16-31 是通用网段，指向不了任何人 |
| 公共 DNS | **原样保留** | 223.5.5.5 这类地址是公开服务，几千万人在用；抹掉 DNS 那节就没法看了 |
| IPv6 | 留前两组，其余打码 | 前 64 位是运营商前缀，后 64 位是接口标识，等于设备指纹 |
| `C:\Users\<名>` | 用户名 → `***` | 路径里直接就是登录名 |

三个容易踩的点：

1. **四份产物都要过脱敏，不能只脱系统信息那一份。** 报告和 json 里同样带着主机名和
   公网出口 IP。代码里只有一个 `Sanitize` 出口，四份都从它走 ——
   以后新增产物也不会漏。
2. **必须幂等。** 脱敏结果再脱敏一次不能变样，否则「导出时脱敏 + 事后手动再跑一遍」
   会把 IPv6 越打越长。做法是匹配到已经含 `*` 的片段直接跳过，
   并且 IPv6 的完整写法正则要求**每组非空**（允许空组的话，打码后那串
   `:****:****:` 里的连续冒号会被再次当成地址匹配）。
3. **脱敏后的 json 还得是合法 json。** 替换只动字符、不动引号逗号，
   但这条必须有断言守着 —— 不然收件人拿到的是一份坏文件，而且从体积上完全看不出来。

### 诊断包里的 GBK 处理

`ipconfig` 是原生程序，输出走系统 ANSI 代码页（中文系统为 GBK）。
在 PowerShell 里必须切换编码再切回：

```powershell
[Console]::OutputEncoding = [System.Text.Encoding]::GetEncoding(936)
$ipcfg = ipconfig /all | Out-String -Width 200
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
```

### 发布参数不能写死在 csproj 里

`EnableCompressionInSingleFile` 仅支持自包含模式，写死在 csproj 会导致
精简版发布报 `NETSDK1176`。应全部由命令行按版本传入。
