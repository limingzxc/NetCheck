# NetCheck 网络体检

一个可以发给别人的 Windows 桌面小工具，检测：本机网卡 / IPv6 / 公网出口 IP（含归属地）/ 网络延迟 / 丢包 / 抖动 / DNS 服务器与劫持 / NAT 类型 / 下载带宽 / 路由追踪（每一跳标归属地）/ 端口连通性 / 路径 MTU / HTTP·HTTPS 分级连通性。

**单文件 exe，目标机器无需安装任何东西，双击即用。**

---

## 目录结构

```
NetCheckCSharp/        C# / WPF 版（唯一在维护的实现）
  Core/                18 个纯逻辑模块，不依赖界面，可单独测试
  Ui/                  ReportView 数据模型 + WPF 渲染器
  App.xaml             配色、按钮、菜单、滚动条等全局样式
  MainWindow.xaml(.cs) 主界面与任务调度
  build.py             发布脚本（独立版 / 精简版，中文输出）
  README.md            ← 详细文档看这里

build.bat              发布入口：一键 publish 出两个版本的单文件 exe（双击即用）
check.py               开发检查：编译 + 单元测试，可加 --e2e / --publish
CODE_REVIEW.md         代码审查标准与流程（分层标准、检查清单、审查记录）
CoreTest/              单元测试（零 NuGet 依赖）
e2e.ps1                端到端集成测试
shots/                 界面截图与测试输出
```

> 根目录原来同时有 `build.bat` 和 `build.py`，一个管发布、一个管开发检查，
> 光看名字分不出谁是谁。现在 `build.bat` 是唯一的发布入口，开发检查叫 `check.py`。

## 快速开始

```bash
cd NetCheckCSharp
dotnet run                      # 直接运行
```

要编译成可分发版本，**双击根目录的 `build.bat`** 即可（也可以 `build.bat standalone` 只出独立版、`build.bat lite` 只出精简版、`build.bat help` 看用法）。
产物在 `NetCheckCSharp/publish/`，每个版本就是一个单文件 exe，直接发那个文件就行。

| 版本 | 体积 | 适用场景 |
|---|---|---|
| `NetCheck-standalone` | 62.9 MB | 目标机器可能没装 .NET → 用这个 |
| `NetCheck-lite` | 478 KB | 确认对方装了 .NET 8 桌面运行时 |

## 界面

一个检测项一张卡片，**卡片标题栏右侧的按钮就是它的运行入口**，检测结果直接填在同一张卡片里 —— 一个功能只有一个地方能点到，按钮和它要填充的展示区不分离。

卡片可以折叠，折叠状态会记住；标题栏上的数字角标表示该检测项下有待处理的问题。
**概览卡片的角标是全部问题的总数**（因为它本身就是那份问题清单），
而问题清单里的每一条都可以点击，直接跳到对应的检测项卡片。

卡片按「常用 / 高级」两级分组。**高级区再按诊断语义分了三层**（网络路径 / 连接能力 / 协议），
「NAT 和端口都属于连接建立能力」「路由和 MTU 都属于路径诊断」这两句话就直接长在界面上，
不用用户自己归纳。高级组默认收起 —— 日常体检根本用不到它们。

```
常用
┌─ 检测选项   目标 223.5.5.5 · 默认目标（公共 DNS）（3 个端口）· 并发 64 ─┐
├─ 概览  ④   公网出口 IP · 网络延迟 · 丢包 · 抖动 · 下载带宽  [一键检测]   │
├─ 本机网络配置  网卡 · 网关 · DNS · 代理环境变量            [重新读取]     │
├─ 公网出口 IP   原生 UDP 与 HTTP 多路径对比          [出口 IP 检测]       │
├─ 连通性 ②   延迟 / 丢包 / 抖动（网页·视频·游戏）· 下载带宽             │
│                                          [延迟检测][带宽测速]           │
└─ DNS    ①   解析耗时 · 劫持检测 · 多服务器对比              [DNS 检测]   │

高级（默认收起）
├─ 网络路径
│  └─ 路径       逐跳路由 · 路径 MTU                [路由追踪][MTU 探测]   │
├─ 连接能力
│  ├─ NAT 类型 ① STUN 判定，影响 P2P 直连与打洞成功率 [NAT 类型检测]      │
│  └─ 端口       TCP 连通性检测                            [端口检测]     │
└─ 协议
   ├─ IPv4 / IPv6  地址分配 · 出口 · 国内/国外可达性       [IPv6 检测]     │
   └─ HTTP / HTTPS 按 DNS → TCP → TLS → HTTP 分级定位   [网页连通性检测]  │
```

打开程序会自动读取「本机网络配置」—— 读网卡是纯本地操作，几十毫秒完成、零流量消耗。
**其余检测都不会自动执行**，尤其是带宽测速（消耗流量）和 NAT 检测（依赖 UDP，在限制 UDP 的网络里会长时间超时）。

**「一键检测」会把上面十一个检测项依次跑一遍**（和命令行的 `--check all` 用的是同一张顺序表），
顺序按诊断链从近到远排：本机 → 公网出口 → DNS → 延迟 → 带宽 → IPv6 → 网页 → NAT → 路由 → MTU → 端口。
以前它只跑其中四项，点完还得手动再点六下。

### 三个值得单说的检测项

**公网出口 IP** 拆成了独立卡片：出口地址、延迟、DNS 以前都塞在「概览」里，
想单独重查一次出口就得把整个概览重跑一遍。现在每张卡片都有能独立把它跑出数据的按钮。

**DNS** 卡片把「当前 DNS」和「对比 DNS」分成了两段 —— 前者是本机网卡上配的，
后者只是拿来比一比的公共 DNS（223.5.5.5 / 119.29.29.29 / 114.114.114.114 / 8.8.8.8）。
分开是为了回答一个「当前 DNS 36 ms」永远回答不了的问题：**换个 DNS 会不会更快**。
两段用的是同一个域名，数字才能横向比；结论会直接写「换用 223.5.5.5 可能明显更快」或者
「当前 DNS 比公共 DNS 还快，不用换」。

> 如果当前 DNS 是局域网地址（多半是路由器），它的耗时只代表**到路由器的往返**，
> 不含路由器往上递归的时间 —— 卡片会明说这两个数字不能直接比，
> 而不是拿 0.5 ms 去和公共 DNS 的 7 ms 比出一个「慢 14 倍」的假结论。
> 对比段也**刻意不按绝对阈值上色**：这些服务器你没有在用，给它们标红等于报一个你修不了的故障。

「值得换」这句话不只是画个颜色 —— 它同时在**问题与提示**里生成一条条目
（「可以换个更快的 DNS（省 N ms）」，点进去跳回 DNS 卡片）。
反过来，当结论是「不用换 / 相当 / 当前是局域网」时，一条条目都不会有。
判断逻辑只有一个函数，界面和清单共用它，两边不会各说各话。

**HTTP / HTTPS** 是唯一「只看域名不看 IP」的一项。它把一次网页访问拆成
DNS → TCP(443) → TLS → HTTP 四层**严格串行**跑，第一层失败就停 —— 因为「卡在第几层」本身就是结论：
「能解析但连不上」和「连上了但 TLS 失败」是两种完全不同的问题，只说「网站打不开」对排查毫无帮助。
默认探测百度 / 腾讯网（国内）+ Cloudflare（境外），境外那个不通本身就是有用信息（能不能上外网）。
自己填的目标会追加在后面。

> 实现上用裸 socket 而不是 `HttpClient`：后者把这四层揉在一起，失败时只给一句「连接被关闭」，
> 而这正是本项要回答的问题。证书走默认校验 —— 证书过期或域名不匹配本身就是体检要发现的问题，放行等于把它藏起来。

显示的 IP 右边会跟上归属地（出口 IP、DNS 服务器、路由每一跳）。私有地址直接标「局域网」，不发请求；
查得到的写成「华东 电信」这种中文，多出口时一眼就能看出两个出口分别落在哪里、第几跳出境。

「诊断包」是把报告 + 原始数据 + 系统网络命令输出打成一个 zip，方便发给运维。
它有两个版本：**原始**版内容完整；**脱敏**版会把主机名、MAC、公网出口 IP 打码，
局域网 IP 和公共 DNS 保留 —— 要发到论坛或群里求助时用这一版。

## 测试

```bash
python check.py            # 编译 + 单元测试（1220 条断言，约 15 秒）
python check.py --e2e      # 再加上端到端集成测试（约 1.5 分钟）
```

三层：单元测试（不碰网络）→ 真实网络检测 → 图形界面集成测试（命令行参数、导出内容、配置持久化）。
