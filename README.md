# NetCheck 网络体检

一个可以直接发给别人的 Windows 桌面小工具，检测：本机网卡 / IPv6 / 公网出口 IP（含归属地）/ 网络延迟 / 丢包 / 抖动 / DNS 服务器与劫持 / NAT 类型 / 下载带宽 / 路由追踪（每一跳标归属地）/ 端口连通性 / 路径 MTU / HTTP·HTTPS 分级连通性。

单文件 exe，目标机器无需安装任何东西，双击即用。

---

## 目录结构

```
NetCheckCSharp/        C# / WPF 版（唯一在维护的实现）
  Core/                18 个纯逻辑模块，不依赖界面，可单独测试
  Ui/                  ReportView 数据模型 + WPF 渲染器 + 主题调色板
  App.xaml             配色、按钮、菜单、滚动条等全局样式
  MainWindow.xaml(.cs) 主界面与任务调度
  build.py             发布脚本（独立版 / 精简版，中文输出）
  README.md            详细文档看这里

build.bat              发布入口：一键 publish 出两个版本的单文件 exe
check.py               开发检查：编译 + 单元测试，可加 --e2e / --publish
CODE_REVIEW.md         代码审查标准与流程
CoreTest/              单元测试（零 NuGet 依赖）
e2e.ps1                端到端集成测试
shots/                 界面截图与测试输出
```

根目录原来同时有 `build.bat` 和 `build.py`，一个管发布、一个管开发检查，光看名字分不出谁是谁。现在 `build.bat` 是唯一的发布入口，开发检查叫 `check.py`。

## 快速开始

```bash
cd NetCheckCSharp
dotnet run                      # 直接运行
```

要编译成可分发版本，双击根目录的 `build.bat` 即可（也可以 `build.bat standalone` 只出独立版、`build.bat lite` 只出精简版、`build.bat help` 看用法）。产物在 `NetCheckCSharp/publish/`，每个版本就是一个单文件 exe，直接发那个文件就行。

| 版本 | 体积 | 适用场景 |
|---|---|---|
| `NetCheck-standalone` | 63.0 MB | 目标机器可能没装 .NET，用这个 |
| `NetCheck-lite` | 0.6 MB | 确认对方装了 .NET 8 桌面运行时 |

## 界面

左边一列导航，右边一块详情面板。导航栏里每个检测项都带一个状态点（绿=正常、橙=有提醒、红=有严重问题、灰=还没测）和一个问题数角标，所以**不用逐个点开就知道哪几项有问题**。选中项用主色竖标 + 浅色底标出。

详情面板顶部是当前检测项的名字、一句说明，和它的运行按钮。一个功能只有一个地方能点到：按钮和它要填充的展示区在同一块面板里。

```
┌ NetCheck 网络体检 │ 文件 检测 视图 帮助                             ☀ ┐
├ [一键检测] [取消]                 复制全文 导出报告 诊断包 脱敏包 ┤
├──────────────┬──────────────────────────────────────────────────┤
│ 常用          │ 概览                              [一键检测]      │
│  概览      ④ │ 公网出口 IP · 网络延迟 · 丢包 · 抖动 · 下载带宽   │
│  本机网络配置 │ ┌──────────────────────────────────────────────┐ │
│  公网出口 IP │ │ ✕ 发现 1 项严重问题          检测时间 15:20   │ │
│  连通性    ② │ │   公网出口 3 个 · 延迟 7.2 ms · 丢包 0.0%     │ │
│  DNS       ① │ └──────────────────────────────────────────────┘ │
│ 高级          │ ┌────────┐┌────────┐┌────────┐                  │
│  网络路径     │ │公网出口││网络延迟││丢包率  │                  │
│   路径        │ │3 个    ││7.2 ms  ││0.0%    │                  │
│  连接能力     │ └────────┘└────────┘└────────┘                  │
│   NAT 类型 ① │ ...                                              │
│   端口        │                                                  │
│  协议         │                                                  │
│   IPv4 / IPv6 │                                                  │
│   HTTP/HTTPS① │                                                  │
│ 配置          │                                                  │
│  检测选项     │                                                  │
└──────────────┴──────────────────────────────────────────────────┘
```

概览页是仪表盘：最上面一条结论横幅（状态标记 + 一句话结论 + 关键指标摘要 + 检测时间），下面是六张指标块、结论胶囊、问题清单和检测摘要表。结论只由问题清单推导，和角标、状态点用的是同一份数据，不会出现「角标说有 2 个问题、横幅说一切正常」这种自相矛盾。

分组沿用「常用 / 高级」两级，高级区再按诊断语义分三层（网络路径 / 连接能力 / 协议），「NAT 和端口都属于连接建立能力」「路由和 MTU 都属于路径诊断」这两句话直接写在导航栏上，不用用户自己归纳。检测选项不混在检测项里，单独归到「配置」下——它是改参数的地方，不是一种「检查」。

导航选择会记住，下次打开停在上次那一项；配置里写了不存在的项就退回概览并把回退写回配置。

打开程序会自动读取「本机网络配置」，读网卡是纯本地操作，几十毫秒完成、零流量消耗。其余检测都不会自动执行，尤其是带宽测速（消耗流量）和 NAT 检测（依赖 UDP，在限制 UDP 的网络里会长时间超时）。点任意一个检测按钮会先切到它那一页再跑——跑完却停在别的页面上等于什么都没看见。

界面有浅色与深色两套主题，默认跟随 Windows 的应用模式设置。标题栏右侧的太阳 / 月亮按钮、`Ctrl+T` 或「视图」菜单都能切换，想固定成某一种（或明确指定「跟随系统」）走菜单。切换是就地换色、不重建界面，检测跑到一半切也不会被打断；系统标题栏也会一起变暗。

「一键检测」会把上面十一个检测项依次跑一遍，和命令行的 `--check all` 用的是同一张顺序表。顺序按诊断链从近到远排：本机 → 公网出口 → DNS → 延迟 → 带宽 → IPv6 → 网页 → NAT → 路由 → MTU → 端口。以前它只跑其中四项，点完还得手动再点六下。

### 三个值得单说的检测项

公网出口 IP 拆成了独立卡片。出口地址、延迟、DNS 以前都塞在「概览」里，想单独重查一次出口就得把整个概览重跑一遍。现在每张卡片都有能独立把它跑出数据的按钮。

DNS 卡片把「当前 DNS」和「对比 DNS」分成了两段：前者是本机网卡上配的，后者只是拿来比一比的公共 DNS（223.5.5.5 / 119.29.29.29 / 114.114.114.114 / 8.8.8.8）。分开是为了回答一个「当前 DNS 36 ms」永远回答不了的问题：换个 DNS 会不会更快。两段用的是同一个域名，数字才能横向比；结论会直接写「换用 223.5.5.5 可能明显更快」或者「当前 DNS 比公共 DNS 还快，不用换」。

如果当前 DNS 是局域网地址（多半是路由器），它的耗时只代表到路由器的往返，不含路由器往上递归的时间，卡片会明说这两个数字不能直接比，而不是拿 0.5 ms 去和公共 DNS 的 7 ms 比出一个「慢 14 倍」的假结论。对比段也刻意不按绝对阈值上色：这些服务器你没有在用，给它们标红等于报一个你修不了的故障。

「值得换」这句话不只是画个颜色，它同时在「问题与提示」里生成一条条目（「可以换个更快的 DNS（省 N ms）」，点进去跳回 DNS 卡片）。反过来，当结论是「不用换 / 相当 / 当前是局域网」时，一条条目都不会有。判断逻辑只有一个函数，界面和清单共用它，两边不会各说各话。

HTTP / HTTPS 是唯一只看域名不看 IP 的一项。它把一次网页访问拆成 DNS → TCP(443) → TLS → HTTP 四层严格串行跑，第一层失败就停，因为「卡在第几层」本身就是结论：「能解析但连不上」和「连上了但 TLS 失败」是两种完全不同的问题，只说「网站打不开」对排查毫无帮助。默认探测百度 / 腾讯网（国内）+ Cloudflare（境外），境外那个不通本身就是有用信息（能不能上外网）。自己填的目标会追加在后面。

实现上用裸 socket 而不是 `HttpClient`：后者把这四层揉在一起，失败时只给一句「连接被关闭」，而这正是本项要回答的问题。证书走默认校验，证书过期或域名不匹配本身就是体检要发现的问题，放行等于把它藏起来。

显示的 IP 右边会跟上归属地（出口 IP、DNS 服务器、路由每一跳）。私有地址直接标「局域网」，不发请求；查得到的写成「华东 电信」这种中文，多出口时一眼就能看出两个出口分别落在哪里、第几跳出境。

「诊断包」是把报告 + 原始数据 + 系统网络命令输出打成一个 zip，方便发给运维。它有两个版本：原始版内容完整；脱敏版会把主机名、MAC、公网出口 IP 打码，局域网 IP 和公共 DNS 保留。要发到论坛或群里求助时用脱敏版。

## 测试

```bash
python check.py            # 编译 + 单元测试（1260 条断言，约 15 秒）
python check.py --e2e      # 再加上端到端集成测试（约 2 分钟）
```

三层：单元测试（不碰外网）→ 真实网络检测 → 图形界面集成测试（命令行参数、导出内容、配置持久化）。
